# UX 通用規則

跨專案的互動與版面規則：同一個功能在 PC 與手機該怎麼呈現、觸控怎麼處理、載入怎麼回饋。視覺（色彩、字級、圓角）見 [design-rules.md](design-rules.md)；兩個組件都像時怎麼選見 [decision-guide.md](decision-guide.md)。

> **套件不提供「桌面 Dialog／手機 Drawer」的包裝元件**：各專案自行封裝，用 `@coss-app/ui/hooks/use-mobile` 的 `useIsMobile()` 或專案自己的 media query hook 切換 `Dialog`／`Drawer`，內容抽成共用元件，行為照本文。**不要**為此另加 bottom sheet 套件。

## 1. 斷點與判斷原則

- 斷點沿用 Tailwind：手機 `< md`（768px）、平板 `md`–`lg`、桌面 `≥ lg`（1024px）。**mobile-first**：先寫手機樣式，再用 `md:`、`lg:` 往上加。
- **寬度決定版面，指標能力決定互動。**
  - 版面（Dialog 或 Drawer、表格或卡片）看寬度。
  - 「是不是觸控」看能力：用 `(hover)`／`(pointer)` media query、Tailwind `pointer-coarse:`。不用 `navigator.userAgent`，也不用寬度推斷。iPad 同時有觸控與滑鼠。
  - `useIsMobile()` 是**寬度**判斷，只用在版面切換，不能拿來決定 hover 或點擊行為。
- 驗收寬度 375／768／1024／1440，再加真機。模擬器測不到 sticky hover、點擊延遲、safe area、軟鍵盤；只在桌面寬度看過不算完成。

## 2. 浮層與選擇器：手機一律底部 Drawer

手機上不留浮動的下拉、選單、Popover。

| 元件 | 桌面 `≥ md` | 手機 `< md` |
| --- | --- | --- |
| 短彈窗（確認、≤ 3 欄） | 置中 `Dialog` | 底部 `Drawer`，可下滑關閉；主要按鈕固定在底部並補 safe area |
| 確認框（刪除、停用、放棄變更） | `AlertDialog` | 底部 `Drawer`；確認在上、取消在下，皆滿寬 |
| 長表單（新增資料、多欄位）；判斷標準與路由見下方「短彈窗或長表單？」 | 置中 `Dialog` | **全螢幕頁面**：路由切換、標題列左側返回鈕、送出鈕黏底；表單本體抽成共用元件兩邊共用 |
| 表單下拉 `Select` | 浮動清單 | `Drawer`＋48px 選項列，選了就關、目前選項打勾；可分組、帶圖示與說明 |
| 列表篩選 | 下拉膠囊 | 搜尋框＋「篩選」鈕（顯示已選數量）→ 面板列出各條件與「清除篩選」，點條件疊第二層選項 Drawer |
| 日期 | `Popover`＋`Calendar` | `Drawer` |
| 多選下拉（標籤、負責人等「點開才出現可複選清單」） | `Combobox` 多選（`ComboboxChips`） | `Drawer`＋48px 勾選列，頂端搜尋框（選項 > 10 必備），底部固定「確認」鈕（顯示已選數量）；勾選當下不關閉 |
| 動作選單 `DropdownMenu`、頭像選單 | 下拉（可有子選單） | `Drawer`；子選單（主題、語言）改成分段按鈕直接切換 |
| 說明 ⓘ、表情等小面板 `Popover` | `Popover` | `Drawer`；本身已在 Drawer 內時改就地展開 |
| 通知面板 | `Popover` | 由右往左滑出的整高 `Drawer`（`swipeDirection="right"`，往右滑關閉） |
| 側欄 | 固定 260px | 左側抽屜（`Sidebar` 自動處理） |

### 短彈窗或長表單？

滿足**全部**條件才是短彈窗（手機 `Drawer`）；任一條不符就是長表單（手機換頁）：
- 欄位 ≤ 3 個，且都是單行輸入、下拉、日期這類短控制項。
- 沒有 `Textarea`、檔案上傳、可新增／刪除的動態列、分步流程。
- 內容在手機（375×667）開著軟鍵盤時仍放得下，不需要在 `Drawer` 內捲動。

「≤ 3 欄」是 jc-serv-ops 的既有準則；後兩條是為避免 `Drawer` 加軟鍵盤擠壓內容所補的判斷，拿不準就當長表單。

**長表單的路由與行為：**
- **有獨立路由**（如 `/cases/new`、`/people/[id]/edit`）。PC 與手機都能直接開網址、重新整理、分享連結；頁面自己在 server 端驗權限，無權就轉回列表。
- **入口依點擊當下的寬度分流**：≥ md 開彈窗（不換路由）；< md `router.push` 到該頁面。用 `useIsMobile()`（`@coss-app/ui/hooks/use-mobile`，< 768px）或專案自己的 media query hook，不用 UA。
- **PC 直接開網址**：照樣渲染頁面版（同一個頁面外框），不自動彈窗、不轉址。
- **表單本體只寫一份**，抽成共用元件，用 `variant="dialog" | "page"` 區分外框；不要為兩種版面各寫一套欄位與驗證。
- **頁面版外框**：標題列左側返回鈕（粗指標 ≥ 44px）、送出鈕黏在底部（補 safe area）。
- **返回**：從站內點進來用 `router.back()`；直接開網址沒有上一頁，`replace` 回列表。
- **送出成功用 `replace` 回列表**，不留空白表單在歷史紀錄，否則返回會回到空表單。
- **未儲存變更**：返回鈕先跳「放棄變更」確認框；重新整理、關分頁用 `beforeunload` 擋。瀏覽器返回手勢與側欄連結攔不到，這是已知限制，不要硬擋。

- **選項超過 10 個自動可搜尋**：桌面改 `Combobox`（頂端搜尋框），手機 `Drawer` 頂端搜尋框；比對選項文字與分組名稱。
- **不疊 Drawer**：彈窗或 Drawer 裡不再開 Drawer。唯一例外是「篩選」面板內的選擇器、彈窗內的 `Select` 疊成第二層。彈窗內「選人」這類情境，直接在 Drawer 內列「搜尋框＋清單」。
- **直接顯示在頁面上的 Checkbox、Radio 維持 inline**，不收進 Drawer（本來就不是浮層）。Radio 超過 6–7 個改 `Select`（手機即 Drawer）。
- **「點開才出現」的複選清單一律走多選下拉**：選項超過 5–6 個的 Checkbox 群組不要整排攤在頁面上，改 `Combobox` 多選；手機同樣是 Drawer，與單選的差別是勾選後不自動關閉，由底部「確認」鈕關閉。單選 Drawer 則維持「選了就關」。
- `HoverCard`、`Tooltip` 只放補充資訊（觸控裝置看不到）；必要資訊要有點擊也能取得的替代。
- `NativeSelect` 是不想引入 Drawer 時的簡易替代，不是首選。
- 表單有未儲存變更時，離開前先跳確認框（放棄變更）。
- 全螢幕圖片預覽、影片這類「內容本身」是例外：所有尺寸都全螢幕，不當彈窗也不當 Drawer。

## 4. 觸控與輸入

- **粗指標（`pointer-coarse:`）下可互動目標 ≥ 44px**，視覺可維持 40px、用內距或 `pointer-coarse:` 加大點擊區。手機選項列 48px。
- **勿停用縮放**：不寫 `user-scalable=no`、`maximum-scale=1`。
- **輸入框字級**：粗指標下 16px，否則 iOS 聚焦時會放大頁面。元件有 `md:text-sm` 時同時加 `md:pointer-coarse:text-base`（iPad 直放 ≥ 768px 才不會放大）。
- **Enter 送出**（對話輸入框）：
  - `(hover: hover) and (pointer: fine)`（PC）：Enter 送出、Shift＋Enter 換行。
  - 手機、iPad（含實體鍵盤）：Enter 換行。
  - ⌘／Ctrl＋Enter 一律送出。
  - **輸入法組字中不送出**（`event.isComposing` 或 `keyCode === 229`）——中日韓使用者選字按 Enter 會誤送。
  - 一般表單的多行欄位不啟用 Enter 送出。
- **hover 樣式只給能 hover 的裝置**（`@media (hover: hover)`），避免觸控後卡住 hover 狀態。

## 5. 視窗高度與 safe area

- App 外框、底部固定 UI 用 `h-dvh`；首屏用 `min-h-svh`。不用 `h-screen`／`100vh`（手機網址列會讓高度溢出）。
- 設定 `viewport-fit=cover`，固定的頂列、底列、貼邊元素補 `env(safe-area-inset-*)`；手機橫放時左右也要補。

## 6. 載入與即時回饋

**點了就要立刻有反應。**

- **使用者的選擇立即生效**：分頁籤、篩選不等 server；資料回來後以 server 為準，失敗時回彈。
- **內容區用骨架，不用整頁 spinner**。骨架版型與真實內容一致（表格保留真實表頭、手機用卡片骨架），避免資料到達時跳版。
- **只在真的有等待時顯示**：載入超過 200ms 才換成骨架，這段時間保留舊內容（不用 CSS `delay-*`——舊內容已卸載會變空白）；骨架一出現至少停留 400ms，避免一閃即逝。
- **周邊保持可用**：工具列、搜尋框不卸載；會再觸發請求的控制項（分頁鈕）載入中停用，避免連點。
- **按鈕送出**：按鈕內左側 `Spinner`、`disabled`、文字改進行式（「送出中」）；不蓋全頁遮罩。
- **首次載入的小區塊**失敗時要給錯誤與重試，不讓骨架一直轉。網址沒有實際變動就不導覽、不進入載入中。
- **樂觀更新**（如對話送出）：立即清空輸入框並顯示半透明的「傳送中」；失敗時淡出，把文字與附件放回輸入框並跳錯誤 toast。

## 7. 導覽與狀態保存

- 列表的篩選、搜尋、頁碼放**網址參數**，重新整理與分享連結都能還原。
- 列表→詳情的返回鈕：站內上一頁就是該列表時走 `history.back()`（保留捲動位置、篩選、頁碼）；否則開這個分頁上次看的列表網址並捲回。不用單純的 `<a href>` 當返回鈕。
- **換頁轉場只做進場**：桌面淡入；手機往下一層由右滑入、返回由左滑入、同層只淡入。使用者偏好減少動態時只淡入。

## 8. 可及性

- 互動元素用 `button`／`a`，不用可點的 `div`。純圖示鈕有 `aria-label`；裝飾圖示 `aria-hidden`。
- 每個欄位有 label；錯誤用 `aria-invalid`＋`aria-describedby` 關聯；必填不只靠顏色。
- `Dialog`／`Drawer` 有標題（可 `sr-only`）、Esc 關閉、焦點陷阱，關閉後焦點回到觸發元素。
- 狀態不只靠顏色（同時有文字或圖示）；淺色、深色模式文字對比都 ≥ 4.5:1。
- 骨架容器 `role="status"`＋`aria-busy="true"`＋`sr-only` 載入文字，骨架本體 `aria-hidden`；toast、未讀數等動態更新用適當等級的 `aria-live`。
- 表格表頭用 `th scope`，可排序欄位加 `aria-sort`；`<html lang>` 依語系。
