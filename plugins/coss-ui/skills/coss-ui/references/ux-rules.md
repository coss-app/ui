# UX 通用規則

跨專案的互動與版面規則：PC／手機呈現、觸控與手勢、資料呈現、載入回饋。視覺（色彩、字級、圓角）見 [design-rules.md](design-rules.md)；兩個組件都像時怎麼選見 [decision-guide.md](decision-guide.md)。

套件不提供「桌面 Dialog／手機 Drawer」包裝組件。各專案自行封裝：用 `useIsMobile()`（`@coss-app/ui/hooks/use-mobile`）或專案自己的 media query hook 切換 `Dialog`／`Drawer`，內容抽成共用組件，行為照本文。不另加 bottom sheet 套件。

## 1. 斷點與判斷原則

- 斷點沿用 Tailwind：手機 `< md`（768px）、平板 `md`–`lg`、桌面 `≥ lg`（1024px）。mobile-first：先寫手機樣式，再用 `md:`、`lg:` 往上加。
- 寬度決定版面（Dialog 或 Drawer、表格或卡片）；指標能力決定互動。判斷觸控用 `(hover)`／`(pointer)` media query 或 `pointer-coarse:`，不用 `navigator.userAgent`，不用寬度推斷（iPad 同時有觸控與滑鼠）。`useIsMobile()` 是寬度判斷，只用於版面切換，不用於決定 hover 或點擊行為。
- 驗收寬度 375／768／1024／1440＋真機。模擬器測不到 sticky hover、點擊延遲、safe area、軟鍵盤；只在桌面寬度看過不算完成。
- 320px 整頁不得橫向捲動（WCAG 1.4.10 reflow）；表格、程式碼等內部自己捲動的區塊除外。320 只做 reflow 檢查，不列入驗收寬度。

## 2. 浮層與選擇器：手機一律底部 Drawer

手機不留浮動的下拉、選單、Popover。

| 組件 | 桌面 `≥ md` | 手機 `< md` |
| --- | --- | --- |
| 短彈窗（確認、≤ 3 欄） | 置中 `Dialog` | 底部 `Drawer`，可下滑關閉；主要按鈕固定在底部並補 safe area |
| 確認框（只給不可復原的動作：刪除、放棄未存變更） | `AlertDialog` | 底部 `Drawer`；確認在上、取消在下，皆滿寬 |
| 長表單（新增資料、多欄位；判斷與路由見下節） | 置中 `Dialog` | 全螢幕頁面：路由切換、標題列左側返回鈕、送出鈕黏底；表單本體抽成共用組件兩邊共用 |
| 表單下拉 `Select` | 浮動清單 | `Drawer`＋48px 選項列，選了就關、目前選項打勾；可分組、帶圖示與說明 |
| 列表篩選 | 下拉膠囊 | 搜尋框＋「篩選」鈕（顯示已選數量）→ 面板列出各條件與「清除篩選」，點條件疊第二層選項 Drawer |
| 日期 | `Popover`＋`Calendar` | `Drawer` |
| 多選下拉（標籤、負責人等「點開才出現的複選清單」） | `Combobox` 多選（`ComboboxChips`） | `Drawer`＋48px 勾選列，頂端搜尋框（選項 > 10 必備），底部固定「確認」鈕（顯示已選數量）；勾選當下不關閉 |
| 動作選單 `DropdownMenu`、頭像選單 | 下拉（可有子選單） | `Drawer`；子選單（主題、語言）改成分段按鈕直接切換 |
| 說明 ⓘ、表情等小面板 `Popover` | `Popover` | `Drawer`；已在 Drawer 內時改就地展開 |
| 通知面板 | `Popover` | 由右往左滑出的整高 `Drawer`（`swipeDirection="right"`，往右滑關閉） |
| 側欄 | 固定 260px | 左側抽屜（`Sidebar` 自動處理） |

### 短彈窗或長表單

**全部**符合才是短彈窗（手機 `Drawer`）；任一不符就是長表單（手機換頁）；拿不準當長表單：
- 欄位 ≤ 3 個，且都是單行輸入、下拉、日期這類短控制項。
- 沒有 `Textarea`、檔案上傳、可新增／刪除的動態列、分步流程。
- 手機（375×667）開著軟鍵盤時內容仍放得下，不需要在 `Drawer` 內捲動。

### 長表單的路由與行為

- 有獨立路由（如 `/cases/new`、`/people/[id]/edit`）：PC 與手機都能直接開網址、重新整理、分享；頁面在 server 端驗權限，無權轉回列表。
- 入口依點擊當下的寬度分流：`≥ md` 開彈窗（不換路由），`< md` `router.push` 到該頁面。寬度判斷用 `useIsMobile()` 或專案自己的 media query hook，不用 UA。入口寫成指向該頁面的真連結（`<a href="/cases/new">`），`≥ md` 攔截一般點擊改開彈窗，⌘／中鍵仍開頁面版（見「10. 導覽、連結與快捷鍵」）。
- PC 直接開網址：渲染頁面版（同一個頁面外框），不自動彈窗、不轉址。
- 表單本體只寫一份，抽成共用組件，用 `variant="dialog" | "page"` 區分外框；不為兩種版面各寫一套欄位與驗證。
- 頁面版外框：標題列左側返回鈕（粗指標 ≥ 44px）、送出鈕黏底（補 safe area）。
- 返回：從站內進來用 `router.back()`；直接開網址沒有上一頁，`replace` 回列表。送出成功用 `replace` 回列表（否則返回會回到空表單）。
- 未儲存變更：返回鈕先跳「放棄變更」確認框；重新整理、關分頁用 `beforeunload` 擋。瀏覽器返回手勢與側欄連結攔不到，是已知限制，不硬擋。

### 其他浮層規則

- 確認框只給不可復原的動作（刪除、放棄未存變更）。可復原的動作（停用、封存、移出）直接執行並跳帶「復原」按鈕的 toast；確認框用多了，使用者會習慣性直接按確認。
- 選項 > 10 個自動可搜尋：桌面改 `Combobox`（頂端搜尋框），手機 `Drawer` 頂端搜尋框；比對選項文字與分組名稱。
- 不疊 Drawer：彈窗或 Drawer 裡不再開 Drawer。例外：「篩選」面板內的選擇器，以及彈窗內的 `Select`、日期、多選下拉，疊成第二層。彈窗內「選人」這類情境，在 Drawer 內直接列「搜尋框＋清單」。
- 直接顯示在頁面上的 Checkbox、Radio 維持 inline（不是浮層，不收進 Drawer）。Radio > 6–7 個改 `Select`（手機即 Drawer）。
- 「點開才出現」的複選清單一律走多選下拉：選項 > 5–6 個的 Checkbox 群組不整排攤在頁面上，改 `Combobox` 多選；手機同為 Drawer，與單選的差別是勾選後不自動關閉，由底部「確認」鈕關閉。單選 Drawer 維持「選了就關」。
- `HoverCard`、`Tooltip` 只放補充資訊（觸控裝置看不到）；必要資訊要有點擊也能取得的替代。
- `NativeSelect` 是不引入 Drawer 時的簡易替代，不是首選。
- 全螢幕圖片預覽、影片這類「內容本身」是例外：所有尺寸都全螢幕，不當彈窗也不當 Drawer。

## 4. 資料呈現

- **截斷不得擋住資料**：每個欄位各自決定換行、截斷或限制行數，並保證被截斷的值看得到完整內容（`title`、tooltip 或詳情頁）。
  - 換行：用來辨識項目的文字（名稱、詳情頁標題），兩行通常夠。
  - 尾端截斷：開頭就有意義的次要資訊（職稱、描述、最後一則訊息預覽）。
  - 中間截斷：結尾才有差異的值（檔名、同網域 Email、路徑），否則尾端截斷後看起來都一樣。
  - 卡片內多行預覽用 `line-clamp`，讓卡片高度一致。
  - 數字、金額、日期與任何使用者要比對的值不截斷，留足空間。
- 數字加千分位，用 `Intl.NumberFormat` 依語系格式化，不手寫分隔符號。相對時間（「3 天前」）超過約一週改顯示絕對日期；用 `Intl.RelativeTimeFormat`／`Intl.DateTimeFormat`。
- 空狀態：0 筆與搜尋無結果都要有明確空狀態，且分開說明。筆數剛好一頁與多一筆時，分頁與「共 N 筆」不得出錯。≥ 1,000 筆要分頁或虛擬捲動。

## 5. 觸控與輸入

- 粗指標（`pointer-coarse:`）下可互動目標 ≥ 44px：視覺可維持 40px，用內距或 `pointer-coarse:` 加大點擊區。手機選項列 48px。
- 按下（`:active`）當下就有回饋，不等放開。`globals.css` 已關掉瀏覽器點擊閃光，按壓狀態由組件或專案自己給。
- 控制項（按鈕、分頁籤）的文字設 `user-select: none`，避免長按選字；內文與資料必須可選取，不整頁關閉。
- hover 才出現的操作（列表列 •••、hover 才顯示的按鈕）在觸控裝置要常駐，或另有入口。hover 樣式只給能 hover 的裝置（`@media (hover: hover)`），避免觸控後卡住 hover 狀態。
- 鍵盤對應內容：驗證碼 `inputmode="numeric"`、金額 `inputmode="decimal"`、Email `type="email"`、電話 `type="tel"`；帳號與驗證碼加 `autocapitalize="none"`、`autocorrect="off"`；`enterkeyhint`（`send`、`search`、`done`）標示 Enter 鍵動作。
- 不停用縮放：不寫 `user-scalable=no`、`maximum-scale=1`。
- 輸入框字級：粗指標下 16px，否則 iOS 聚焦時放大頁面。組件有 `md:text-sm` 時同時加 `md:pointer-coarse:text-base`（iPad 直放 ≥ 768px 才不放大）。
- **Enter 送出**（僅對話輸入框）：
  - `(hover: hover) and (pointer: fine)`（PC）：Enter 送出、Shift＋Enter 換行。
  - 手機、iPad（含實體鍵盤）：Enter 換行。
  - ⌘／Ctrl＋Enter 一律送出。
  - 輸入法組字中不送出（`event.isComposing` 或 `keyCode === 229`；中日韓選字按 Enter 會誤送）。
  - 一般表單的多行欄位不啟用 Enter 送出。
- 組字中，即時搜尋、自動完成、字數計算也要暫停（`onChange` 在組字時就會觸發，注音打到一半就送出查詢）：判斷 `isComposing`（或 `compositionstart`／`compositionend`），組字結束再處理。
- 即時搜尋：debounce 約 300ms；新查詢用 `AbortController` 取消舊請求，只顯示最新查詢的結果；有內容時提供清除鈕。

## 6. 表單行為

欄位外觀與錯誤元件見 [design-rules.md](design-rules.md)「表單」，這裡只講行為。

- 錯誤顯示時機：離開欄位（blur）或送出時才顯示，不在第一次輸入時逐鍵報錯；顯示過錯誤的欄位改即時驗證，修正後立刻清除。
- 送出失敗：焦點移到第一個錯誤欄位並捲到可見處；已輸入內容不清空；server 錯誤盡量對應到欄位，對不上才放表單頂端。
- 不用停用送出鈕代替錯誤說明（使用者不知道為什麼按不了）：鈕保持可按，按下後指出問題。例外：對話輸入框內容為空時送出鈕可停用。
- `autocomplete` 給標準值：`email`、`username`、`current-password`、`new-password`、`one-time-code`、`tel`、`name`。只用於「使用者填自己的資料」（登入、註冊、個人設定）；客服代客戶輸入他人資料時用 `autocomplete="off"`，否則會自動填成客服自己的 Email。
- 密碼與驗證碼欄位不擋貼上、不擋密碼管理器（WCAG 3.3.8）；同一流程不重複要求已填過的資料（3.3.7）。
- 寬鬆接受、嚴格儲存：去前後空白；全形數字轉半形；電話、統編容許空白與 `-`，存入前再正規化。
- 停用要說明原因：沒有權限的操作隱藏；暫時不能用才停用，並在旁邊用文字說明原因（tooltip 在觸控裝置看不到）。
- 錯誤訊息寫「發生什麼、怎麼處理」（「Email 格式不正確，請檢查是否漏了 @」），不只寫「格式錯誤」或錯誤代碼。
- 檔案上傳：先寫明接受的格式與大小上限，選檔後在 client 端先驗證；顯示進度並可取消；失敗可重試。對話輸入框支援貼上與拖放。

## 7. 手勢

- 拖曳、滑動關閉用套件的 `Drawer`（已處理跟手拖曳、滑動關閉、遮罩隨進度淡出），不自己寫手勢，不另加 Vaul 等套件。
- 從哪裡進來就往哪裡滑掉：底部 Drawer 往下、右側通知往右、toast 照進場方向。
- 手指按住時 1:1 跟手，不加緩動、不延遲；關閉途中可再抓回來，不等動畫播完。
- 可拖曳區域設 `touch-action`，只把拖曳方向交給手勢，避免和頁面捲動互搶；Drawer 內按鈕、輸入框按下時不觸發拖曳。
- 每個拖曳或滑動都要有點擊替代（WCAG 2.5.7）：Drawer 有關閉鈕與「取消」、拖曳排序有「上移／下移」、滑動出現的列操作有選單入口。手勢是加速，不是唯一入口。
- 按住確認（按住刪除這類）：按住時進度等速前進，如實呈現剩餘時間；沒按滿就放開，快速彈回。
- 減少動態（`prefers-reduced-motion`）：保留跟手拖曳（動作是使用者自己做的）；去掉甩動慣性與回彈，放開後只用短的淡出收尾，不做位移（與 `globals.css` 一致）。

## 8. 視窗高度、safe area 與捲動

- App 外框、底部固定 UI 用 `h-dvh`；首屏用 `min-h-svh`。不用 `h-screen`／`100vh`（手機網址列會讓高度溢出）。
- 設定 `viewport-fit=cover`；固定的頂列、底列、貼邊元素補 `env(safe-area-inset-*)`，手機橫放時左右也補。
- 軟鍵盤不得蓋住輸入框與底部固定鈕：聚焦欄位捲到可見處；底部固定列隨鍵盤上移（`viewport` meta 加 `interactive-widget=resizes-content`，或用 `visualViewport`）。只能在真機驗。
- Drawer、彈窗、對話區內的捲動區加 `overscroll-behavior: contain`，捲到底不傳給背景頁面。
- 有黏頂列或黏底列時，捲動容器加 `scroll-padding-top`／`scroll-padding-bottom`，錨點目標加 `scroll-margin-top`，聚焦或跳轉到的元素才不被固定列遮住（WCAG 2.4.11）。

## 9. 載入、回饋與錯誤狀態

點了就要立刻有反應。

- 使用者的選擇立即生效：分頁籤、篩選不等 server；資料回來後以 server 為準，失敗時回彈。
- 內容區用骨架，不用整頁 spinner。骨架版型與真實內容一致（表格保留真實表頭、手機用卡片骨架），避免到達時跳版。
- 載入超過 200ms 才換成骨架，這段時間保留舊內容（不用 CSS `delay-*`：舊內容已卸載會變空白）；骨架一出現至少停留 400ms。
- 周邊保持可用：工具列、搜尋框不卸載；會再觸發請求的控制項（分頁鈕）載入中停用，避免連點。
- 按鈕送出：按下立即擋住重複送出（停用或忽略再次點擊）；超過 300ms 才在按鈕內左側顯示 `Spinner`、文字改進行式（「送出中」），出現後至少停留 400ms（300ms 內完成時閃 spinner 像故障）。不蓋全頁遮罩。
- 首次載入的小區塊失敗時給錯誤與重試，不讓骨架一直轉。網址沒有實際變動就不導覽、不進入載入中。
- 樂觀更新（如對話送出）：立即清空輸入框並顯示半透明「傳送中」；失敗時淡出，文字與附件放回輸入框並跳錯誤 toast。

**Toast 與操作回饋**

- Toast 不是唯一入口：重要結果在頁面上也要看得到（列表更新、狀態變化）。
- 錯誤 toast 不自動消失，或停留比成功更久；帶「復原」的 toast 停留要夠長，滑鼠移上或聚焦時暫停計時（WCAG 2.2.1）。秒數以組件預設為準，不自己寫死。
- 複製鈕：點了圖示換成勾選、文字改「已複製」，約 2 秒後還原。

**錯誤與異常**

- 錯誤頁分情況，各自說明原因並給出口，不只顯示代碼：
  - 401 登入過期：保留填到一半的內容，重新登入後回到原頁。
  - 403 無權限：說明要找誰開通，附回列表的出口。
  - 404：附回列表或搜尋的出口。
  - 500：「我們這邊出問題」，提供重試。
  - 離線：顯示離線提示列，恢復連線後自動重試；離線時送出的內容不丟。
- 多人處理同一份資料（客服常見）：資料被他人更新時顯示提示列，不直接覆蓋使用者正在看或改的內容；即時新進的列表項目不插到使用者眼前的位置，改顯示「N 筆新資料」按鈕，點了才載入。
- 未讀數 > 99 顯示 `99+`。瀏覽器通知權限只在使用者主動操作後才請求，不在載入頁面時跳出。

**效能底線**

- Core Web Vitals 以 p75 為準：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1。
- 圖片與影片給 `width`／`height` 或 `aspect-ratio`（避免 CLS）；首屏以下的圖加 `loading="lazy"`，首屏主圖不加。

## 10. 導覽、連結與快捷鍵

- 列表的篩選、搜尋、頁碼放網址參數，重新整理與分享連結都能還原。
- 列表→詳情的返回鈕：站內上一頁就是該列表時走 `history.back()`（保留捲動位置、篩選、頁碼）；否則開這個分頁上次看的列表網址並捲回。不用單純的 `<a href>` 當返回鈕。
- 導覽用真的 `<a>`（框架的 `Link`，或 `Button render={<a />}`），不用 `onClick` 加 `router.push`，這樣 ⌘／Ctrl 點擊、中鍵、右鍵「在新分頁開啟」才能用。可點的表格列、卡片也要有真連結（標題是 `<a>`，用 CSS 把點擊區撐滿整列）。
- 外部連結加 `target="_blank"`、`rel="noopener noreferrer"`，附外部連結圖示（`aria-hidden`）與「（另開新分頁）」的 `sr-only` 文字；站內連結不另開分頁。
- 快捷鍵：不覆蓋瀏覽器與系統快捷鍵（⌘R、⌘W、⌘F）；依平台顯示 ⌘ 或 Ctrl（用 `Kbd`）；輸入框、可編輯區聚焦時不觸發單鍵快捷鍵；每個快捷鍵動作都要有一般的點擊入口。

## 11. 文案

- 按鈕寫「動詞＋受詞」（「建立工單」「儲存變更」），不寫「確定」「是」「OK」。破壞性確認鈕寫出動作（「刪除工單」）；確認框標題寫出對象與後果（「刪除工單 #1024？刪除後無法復原」）。例外：多選 Drawer 底部的「確認（N）」是確認選擇，可保留。
- 同一概念全站一個詞（「工單」不與「案件」混用，「客服人員」不與「客服專員」混用）；不確定就查專案既有用詞。
- 中英文、數字之間加半形空格（「共 12 筆 Email」）；中文句子用全形標點，英文與數字縮寫內用半形。
- 日期時間預設 `Asia/Taipei`、24 小時制；相對時間旁用 `title` 附完整絕對時間；同一年不顯示年份，跨年才顯示。

## 12. 動態

- 高頻操作不做進出場動畫：每天重複數十次以上的操作（命令面板、快捷鍵觸發的動作、列表列、分頁籤切換的內容）直接切換。動畫只留給低頻、需要交代空間關係的時刻（開彈窗、Drawer、換頁層級）。
- 換頁轉場只做進場：桌面淡入；手機往下一層由右滑入、返回由左滑入、同層只淡入。這是刻意的例外：方向告訴使用者是進入下一層還是返回。
- 使用者偏好減少動態時只淡入；手勢見「7. 手勢」。

## 13. 可及性

- 互動元素用 `button`／`a`，不用可點的 `div`。純圖示鈕有 `aria-label`；裝飾圖示 `aria-hidden`。
- 每個欄位有 label；錯誤用 `aria-invalid`＋`aria-describedby` 關聯；必填不只靠顏色。
- `Dialog`／`Drawer` 有標題（可 `sr-only`）、Esc 關閉、焦點陷阱，關閉後焦點回到觸發元素。
- 焦點管理：換頁後焦點移到 `h1` 或 `main`；刪除列表項目後移到下一項（沒有就移到列表標題）；Esc 一次只關最上層浮層；不移除 `focus-visible` 外框（鍵盤操作時顯示、滑鼠點擊不顯示）。
- 狀態不只靠顏色（同時有文字或圖示）；淺色、深色模式文字對比都 ≥ 4.5:1。
- 文字放大：瀏覽器縮放 200% 或系統大字級時，文字不得被固定高度裁切；包住多行文字的容器不用固定高度。
- 骨架容器 `role="status"`＋`aria-busy="true"`＋`sr-only` 載入文字，骨架本體 `aria-hidden`；toast、未讀數等動態更新用適當等級的 `aria-live`。
- 表格表頭用 `th scope`，可排序欄位加 `aria-sort`；`<html lang>` 依語系。
