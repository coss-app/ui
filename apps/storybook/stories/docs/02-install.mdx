# 安裝

`@coss-app/ui` 是 npmjs 上的公開套件（MIT）。不用 token、不用 `.npmrc`，本機、CI、Vercel、Cloudflare、Docker 都一樣：

```bash
npm install @coss-app/ui
```

## 需求

| 項目 | 版本 |
| --- | --- |
| Node.js | 22 以上 |
| React | 18.2 或 19 |
| Tailwind CSS | v4（v3 專案先看「舊專案遷移」） |

## 確認安裝成功

```bash
npm view @coss-app/ui version
```

印出版本號就代表可用。接下來的設定（全域 CSS、import 寫法）見「新專案」或「舊專案遷移」。

## 從 GitHub Packages 版本切換

以前安裝過 GitHub Packages 版本的專案，照下面做一次，之後就不再需要 token。

1. 刪掉專案 `.npmrc` 裡這兩行（檔案只剩這兩行就整個刪掉）：

   ```ini
   @coss-app:registry=https://npm.pkg.github.com
   //npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
   ```

2. 重新安裝，讓 lockfile 改指向 npmjs：

   ```bash
   npm install @coss-app/ui@latest
   ```

3. 移除 CI、Vercel、Cloudflare、Docker 裡的 `NODE_AUTH_TOKEN`、`packages: read` 與 build secret 設定。這些都用不到了。

`.npmrc` 留著舊設定時，安裝會往 GitHub Packages 找套件，出現 `401` 或 `404`。遇到時先檢查這個檔案。

npmjs 的第一版是 0.1.1。更早的版本只存在 GitHub Packages，不會搬過來。

## 自動檢查寫法是否符合設計規範（選用）

`@coss-app/ui` 附 lint 規則，在 `className` 亂改組件內距、顏色，或寫死色碼、任意值時報錯，並建議該用哪個 variant 或 size。設定方式見 <a href="/?path=/docs/使用手冊-設計規範-lint--docs" target="_top">設計規範 Lint</a>。

## 讓 AI 助理會用這個組件庫（選用）

用 Claude Code 寫畫面的話，可以安裝 `coss-ui` skill，讓 AI 知道組件怎麼選、import 路徑、設計規範與 Base UI 的寫法。安裝、使用與更新方式見 <a href="/?path=/docs/使用手冊-claude-code-skill--docs" target="_top">Claude Code Skill</a>。
