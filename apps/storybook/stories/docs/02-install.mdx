# 安裝與權限

`@coss-app/ui` 發佈在 **GitHub Packages（私有）**。這個文件站公開，但**安裝套件一定要 token**：GitHub Packages 的 npm 套件不論公開或私有，都要登入才能下載。

## 需求

| 項目 | 版本 |
| --- | --- |
| Node.js | 22 以上 |
| React | 18.2 或 19 |
| Tailwind CSS | **v4**（v3 專案先看「舊專案遷移」） |

## 1. 取得 token（每位開發者一次）

1. GitHub → Settings → Developer settings → **Personal access tokens → Tokens (classic)** → Generate new token (classic)。
2. 勾選 **`read:packages`**（只要這個）。期限依公司規定。
3. 你的 GitHub 帳號必須是 `coss-app` org 成員。

> GitHub Packages 的 npm registry **只支援 classic token**，fine-grained token 無法安裝。

把 token 放進 shell 設定（`~/.zshrc` 或 `~/.bashrc`），不要寫進專案：

```bash
export NODE_AUTH_TOKEN=ghp_xxxxxxxxxxxxxxxx
```

## 2. 專案的 `.npmrc`

放在專案根目錄（與 `package.json` 同層），**可以 commit**，裡面只有變數名稱沒有 token：

```ini
@coss-app:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
```

只有 `@coss-app/*` 會去 GitHub Packages，其他套件照常走 npmjs。

**`.npmrc` 不用填 token。** `${NODE_AUTH_TOKEN}` 只是變數名稱，npm 執行時才去讀同名的環境變數：

| 放哪裡 | 內容 | 可以 commit？ |
| --- | --- | --- |
| 專案的 `.npmrc` | `${NODE_AUTH_TOKEN}`（變數名稱，照抄上面即可） | 可以 |
| 環境變數 `NODE_AUTH_TOKEN` | 真正的 token（`ghp_…`） | **不可以** |

環境變數在哪設：本機寫在 shell 設定（上一步）；GitHub Actions 由 workflow 設；Vercel／Cloudflare 在平台後台設（見下方）。不論哪個環境，`.npmrc` 都不用改。

## 3. 安裝

```bash
npm install @coss-app/ui
```

出現 `401 Unauthorized` 或 `404 Not Found`：多半是 `NODE_AUTH_TOKEN` 沒設、token 沒有 `read:packages`，或帳號不在 coss-app org。

## CI 與部署平台

### GitHub Actions（coss-app 內的 repo）

用內建的 `GITHUB_TOKEN` 即可，不需要個人 token。

`GITHUB_TOKEN` 是 GitHub Actions **每次執行時自動產生**的臨時 token，執行結束就失效：**不需要建立，Settings → Secrets 裡也看不到它**，workflow 裡直接寫 `${{ secrets.GITHUB_TOKEN }}` 就能用。它只存在於 Actions，本機開發請用自己的 classic token。

```yaml
permissions:
  contents: read
  packages: read

steps:
  - uses: actions/checkout@v4
  - uses: actions/setup-node@v4
    with:
      node-version: 22
      registry-url: https://npm.pkg.github.com
      scope: "@coss-app"
  - run: npm ci
    env:
      NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

第一次使用的 repo 要先讓它有讀取套件的權限（org 管理員操作一次）：

1. 進入套件頁：**coss-app → Packages → `ui`**，或從 coss-app/ui repo 首頁右側欄的 **Packages** 點進去。
2. 右側 **Package settings** → **Manage Actions access** → **Add repository**，選要安裝套件的 repo，Role 選 **Read**。

> 套件**第一次發佈後**才會出現在 Packages 列表，在那之前看不到 `ui`、也沒有 Manage Actions access。

### Vercel／Cloudflare Pages／其他平台

在專案的環境變數加入 `NODE_AUTH_TOKEN`（值為具 `read:packages` 的 classic token，建議由管理員用共用帳號建立）。`.npmrc` 已在 repo 內，平台安裝時會自動讀取。

### Docker

用 build secret，不要把 token 寫進 image：

```dockerfile
RUN --mount=type=secret,id=npm_token \
    NODE_AUTH_TOKEN=$(cat /run/secrets/npm_token) npm ci
```

```bash
docker build --secret id=npm_token,env=NODE_AUTH_TOKEN .
```
