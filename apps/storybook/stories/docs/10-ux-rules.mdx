# UX 規則

同一個功能在電腦和手機上該怎麼呈現、觸控與手勢怎麼處理、資料怎麼顯示、載入時怎麼回饋，公司各專案都照這一頁做，使用者換專案也不會重新學一次。視覺（色彩、字級、圓角）見「首頁」的設計原則與 repo 內的 `DESIGN.md`；兩個組件都像時怎麼選，見各組件頁與 Claude Code Skill 的選型指南。

AI 助理用 <a href="/?path=/docs/使用手冊-claude-code-skill--docs" target="_top">Claude Code Skill</a> 時會自動讀到同一份規則（`ux-rules.md`），寫畫面時會參照這裡的規範；產出仍要 review。

> 套件不提供「桌面 Dialog、手機 Drawer」的包裝組件，各專案自行封裝（範例見下方「手機改 Drawer 的寫法」）。

## 基本原則

- **mobile-first**：先寫手機樣式，再用 `md:`、`lg:` 往上加。斷點沿用 Tailwind：手機 `< md`（768px）、平板 `md`–`lg`、桌面 `≥ lg`（1024px）。
- **寬度決定版面，指標能力決定互動。** 彈窗用 Dialog 還是 Drawer、表格還是卡片，看寬度；「是不是觸控」看 `(hover)`、`(pointer)` media query 或 Tailwind 的 `pointer-coarse:`。不用 `navigator.userAgent`，也不用寬度推斷：iPad 同時有觸控與滑鼠。
- 套件的 `useIsMobile()`（`@coss-app/ui/hooks/use-mobile`）是**寬度**判斷，只用在版面切換，不能拿來決定 hover 或點擊行為。
- **驗收寬度**：375、768、1024、1440，再加真機。模擬器測不到 hover 殘留、點擊延遲、safe area 與軟鍵盤，只在桌面寬度看過不算完成。
- **320px 不能橫向捲動**（WCAG 1.4.10 reflow）：除了表格、程式碼這類內部自己捲動的區塊，整頁不出現橫向捲軸。320 是 reflow 檢查，不必列入上述驗收寬度。

## 浮層與選擇器：手機一律底部 Drawer

手機上不留浮動的下拉、選單、Popover。

| 組件 | 桌面 `≥ md` | 手機 `< md` |
| --- | --- | --- |
| 短彈窗（確認、≤ 3 欄），如「轉派工單」 | 置中 `Dialog` | 底部 `Drawer`，可下滑關閉；主要按鈕固定在底部並補 safe area |
| 確認框（只給不可復原的動作：刪除工單、放棄未存變更） | `AlertDialog` | 底部 `Drawer`；確認在上、取消在下，皆滿寬 |
| 長表單（建立工單、多欄位） | 置中 `Dialog` | **全螢幕頁面**：換頁、標題列左側返回鈕、送出鈕黏在底部 |
| 表單下拉 `Select`，如「指派給」 | 浮動清單 | `Drawer`＋48px 選項列，選了就關、目前選項打勾；可分組、帶圖示與說明 |
| 列表篩選，如「狀態」「負責人」 | 下拉膠囊 | 搜尋框＋「篩選」鈕（顯示已選數量）→ 面板列出各條件與「清除篩選」，點條件疊第二層選項 Drawer |
| 日期，如「到期日」 | `Popover`＋`Calendar` | `Drawer` |
| 多選下拉，如「標籤」「協作人員」 | `Combobox` 多選（`ComboboxChips`） | `Drawer`＋48px 勾選列，頂端搜尋框，底部固定「確認」鈕（顯示已選數量）；勾選當下不關閉 |
| 動作選單 `DropdownMenu`、頭像選單 | 下拉（可有子選單） | `Drawer`；子選單（主題、語言）改成分段按鈕直接切換 |
| 說明 ⓘ、表情等小面板 `Popover` | `Popover` | `Drawer`；本身已在 Drawer 內時改就地展開 |
| 通知面板 | `Popover` | 由右往左滑出的整高 `Drawer`（`swipeDirection="right"`，往右滑關閉） |
| 側欄 | 固定 260px | 左側抽屜（`Sidebar` 自動處理） |

補充規則：

- **確認框只給不可復原的動作**（刪除工單、放棄未存變更）。可復原的動作（停用帳號、封存工單、移出群組）直接執行，並跳帶「復原」按鈕的 toast。確認框用多了，使用者會習慣性直接按確認。
- **選項超過 10 個自動可搜尋**：桌面改 `Combobox`（頂端搜尋框），手機 `Drawer` 頂端搜尋框；比對選項文字與分組名稱。
- **不疊 Drawer**：彈窗或 Drawer 裡不再開 Drawer。唯一例外是「篩選」面板內的選擇器、彈窗內的 `Select`、日期、多選下拉疊成第二層。彈窗內「選人」這類情境，直接在 Drawer 內列「搜尋框＋清單」。
- **直接顯示在頁面上的 Checkbox、Radio 維持 inline**，不收進 Drawer。Radio 超過 6–7 個改 `Select`。
- **「點開才出現」的複選清單走多選下拉**：選項超過 5–6 個的 Checkbox 群組不要整排攤在頁面上，改 `Combobox` 多選。單選 Drawer 是「選了就關」，多選要按「確認」才關。
- `HoverCard`、`Tooltip` 只放補充資訊（觸控裝置看不到）；必要資訊要有點擊也能取得的替代。
- `NativeSelect` 是不想引入 Drawer 時的簡易替代，不是首選。
- 表單有未儲存變更時，離開前先跳確認框（放棄變更）。
- 全螢幕圖片預覽、影片這類「內容本身」是例外：所有尺寸都全螢幕，不當彈窗也不當 Drawer。

### 手機改 Drawer 的寫法

用 `useIsMobile()` 切換，內容抽成共用組件，呼叫端不必分辨裝置：

```tsx
"use client";

import type { ReactNode } from "react";
import { useIsMobile } from "@coss-app/ui/hooks/use-mobile";
import {
  Dialog,
  DialogContent,
  DialogHeader,
  DialogTitle,
} from "@coss-app/ui/components/dialog";
import {
  Drawer,
  DrawerContent,
  DrawerHeader,
  DrawerTitle,
} from "@coss-app/ui/components/drawer";

export function ResponsiveDialog({
  open,
  onOpenChange,
  title,
  children,
}: {
  open: boolean;
  onOpenChange: (open: boolean) => void;
  title: string;
  children: ReactNode;
}) {
  const isMobile = useIsMobile();

  if (isMobile) {
    return (
      <Drawer open={open} onOpenChange={onOpenChange} showSwipeHandle>
        <DrawerContent>
          <DrawerHeader>
            <DrawerTitle>{title}</DrawerTitle>
          </DrawerHeader>
          <div className="p-5">{children}</div>
        </DrawerContent>
      </Drawer>
    );
  }

  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent>
        <DialogHeader>
          <DialogTitle>{title}</DialogTitle>
        </DialogHeader>
        {children}
      </DialogContent>
    </Dialog>
  );
}
```

確認框、下拉、日期照同一個模式：桌面用對應的浮層，手機換 `Drawer`，選項列高 48px。

## 短彈窗或長表單？

**全部**符合才是短彈窗（手機用 Drawer）；任一條不符就是長表單（手機換頁）：

- 欄位 ≤ 3 個，且都是單行輸入、下拉、日期這類短控制項。
- 沒有 `Textarea`、檔案上傳、可新增或刪除的動態列、分步流程。
- 內容在手機（375×667）開著軟鍵盤時仍放得下，不需要在 Drawer 內捲動。

拿不準就當長表單。

長表單的路由與行為：

- **有獨立路由**（如 `/tickets/new`、`/people/[id]/edit`）。PC 與手機都能直接開網址、重新整理、分享連結；頁面自己在 server 端驗權限，無權就轉回列表。
- **入口依點擊當下的寬度分流**：`≥ md` 開彈窗（不換路由），`< md` `router.push` 到該頁面。入口寫成指向該頁面的真連結（`<a href="/tickets/new">`），`≥ md` 時攔截一般點擊改開彈窗，⌘／中鍵仍開頁面版（見下方「導覽、連結與快捷鍵」）。
- **PC 直接開網址**：照樣顯示頁面版，不自動彈窗、不轉址。
- **表單本體只寫一份**，抽成共用組件，用 `variant="dialog"` 或 `variant="page"` 區分外框；不要為兩種版面各寫一套欄位與驗證。
- **頁面版外框**：標題列左側返回鈕、送出鈕黏在底部（補 safe area）。
- **返回**：從站內點進來用 `router.back()`；直接開網址沒有上一頁，`replace` 回列表。送出成功也用 `replace` 回列表，避免返回時回到空白表單。
- **未儲存變更**：返回鈕先跳「放棄變更」確認框；重新整理、關分頁用 `beforeunload` 擋。瀏覽器返回手勢與側欄連結攔不到，這是已知限制，不要硬擋。

## 資料呈現

**截斷不能擋住資料。** 每個欄位各自決定換行、截斷或限制行數，並保證被截斷的值看得到完整內容（`title`、tooltip 或詳情頁）：

| 做法 | 用在 | 例子 |
| --- | --- | --- |
| 換行（兩行通常夠） | 用來辨識項目的文字 | 客戶名稱、工單標題 |
| 尾端截斷 | 開頭就有意義的次要資訊 | 職稱、描述、最後一則回覆預覽 |
| 中間截斷 | 結尾才有差異的值 | `報價單…v12-final.pdf`、同網域的 Email、路徑 |
| 限制行數 `line-clamp` | 卡片內的多行預覽 | 工單卡片的問題描述 |
| **不截斷** | 數字、金額、日期與任何要比對的值 | 工單編號、退款金額、到期日 |

- **數字與時間格式**：數字加千分位，用 `Intl.NumberFormat` 依語系格式化，不手寫分隔符號；相對時間（「3 天前」）超過約一週改顯示絕對日期，用 `Intl.RelativeTimeFormat`、`Intl.DateTimeFormat`。
- **空狀態與大量資料**：0 筆、搜尋無結果都要有明確的空狀態，且兩者分開說明；筆數剛好一頁與多一筆時，分頁與「共 N 筆」不能出錯；1,000 筆以上要分頁或虛擬捲動。

## 觸控與輸入

- **粗指標（`pointer-coarse:`）下可互動目標 ≥ 44px**，視覺可維持 40px，用內距或 `pointer-coarse:` 加大點擊區。手機選項列 48px。
- **按下當下就有回饋**：可點元素在按下時（`:active`）就變化，不等放開。`globals.css` 已關掉瀏覽器的點擊閃光，按壓狀態由組件或專案自己給。
- **長按選字**：按鈕、分頁籤等控制項的文字不能被長按選取（`user-select: none`）；內文與資料必須可以選取，不整頁關閉。
- **hover 才出現的操作**（工單列表列的 •••、hover 才顯示的按鈕）在觸控裝置要常駐，或另有入口。
- **鍵盤對應內容**：驗證碼 `inputmode="numeric"`、金額 `inputmode="decimal"`、Email `type="email"`、電話 `type="tel"`；帳號與驗證碼加 `autocapitalize="none"`、`autocorrect="off"`；`enterkeyhint`（`send`、`search`、`done`）讓 Enter 鍵標示它的動作。
- **勿停用縮放**：不寫 `user-scalable=no`、`maximum-scale=1`。
- **輸入框字級**：觸控裝置下 16px，否則 iOS 聚焦時會放大頁面。`globals.css` 已對 `input`、`textarea`、`select` 處理；組件有 `md:text-sm` 時，同時加 `md:pointer-coarse:text-base`（iPad 直放時才不會放大）。
- **Enter 送出**（對話輸入框，如工單回覆）：
  - 電腦（`(hover: hover) and (pointer: fine)`）：Enter 送出、Shift＋Enter 換行。
  - 手機、iPad（含實體鍵盤）：Enter 換行。
  - ⌘／Ctrl＋Enter 一律送出。
  - **輸入法組字中不送出**（`event.isComposing` 或 `keyCode === 229`）。中文使用者選字按 Enter 會誤送。
  - 一般表單的多行欄位不啟用 Enter 送出。
- **輸入法組字中，即時搜尋、自動完成、字數計算也要暫停**：`onChange` 在組字時就會觸發，注音打到一半就送出查詢。判斷 `isComposing`（或 `compositionstart`、`compositionend`），組字結束再處理。
- **即時搜尋**（如搜尋客戶）：debounce 約 300ms；新查詢取消舊請求（`AbortController`），只顯示最新查詢的結果，避免慢的舊回應蓋掉新的；有內容時提供清除鈕。
- **hover 樣式只給能 hover 的裝置**（`@media (hover: hover)`），避免觸控後卡住 hover 狀態。

## 表單行為

欄位外觀與錯誤元件見「首頁」的設計原則與各表單組件頁，這裡只講行為。

- **錯誤顯示時機**：離開欄位（blur）或送出時才顯示，不在第一次輸入時逐鍵報錯；顯示過錯誤的欄位改成即時驗證，修正後立刻清除。
- **送出失敗**：焦點移到第一個錯誤欄位並捲到可見處；已輸入的內容不清空；server 回的錯誤盡量對應到欄位，對不上才放表單頂端。
- **不用停用送出鈕代替錯誤說明**：使用者不知道為什麼按不了。鈕保持可按，按下後指出哪裡有問題。例外：對話輸入框內容為空時，送出鈕可停用（沒有東西可送，不算錯誤）。
- **`autocomplete`**：`email`、`username`、`current-password`、`new-password`、`one-time-code`、`tel`、`name` 等標準值要給，瀏覽器與密碼管理器才能自動填。只用在「使用者填自己的資料」（登入、註冊、個人設定）；客服代客戶輸入他人資料時用 `autocomplete="off"`，否則會自動填成客服自己的 Email。
- **密碼與驗證碼欄位不擋貼上**，也不擋密碼管理器（WCAG 3.3.8）；同一流程不重複要求使用者已填過的資料（3.3.7）。
- **寬鬆接受、嚴格儲存**：去掉前後空白；全形數字轉半形；電話、統編容許空白與 `-`，存入前再正規化。
- **停用要說明原因**：沒有權限的操作隱藏；暫時不能用才停用，並在旁邊用文字說明原因（tooltip 在觸控裝置看不到）。
- **錯誤訊息**寫「發生什麼、怎麼處理」（「Email 格式不正確，請檢查是否漏了 @」），不只寫「格式錯誤」或錯誤代碼。
- **檔案上傳**（如工單附件）：先寫明接受的格式與大小上限，選檔後在 client 端先驗證；顯示進度並可取消；失敗要能重試。對話輸入框支援貼上與拖放。

## 手勢

- **拖曳、滑動關閉用套件的 `Drawer`**，不自己寫手勢，也不另加 Vaul 等套件；它已處理跟手拖曳、滑動關閉、遮罩跟著拖曳進度淡出。
- **從哪裡進來就往哪裡滑掉**：底部 Drawer 往下滑、右側通知往右滑、toast 照進場方向滑掉。進出同一個方向，使用者不用學就會。
- **手指按住時 1:1 跟手**，不加緩動、不延遲；**關閉途中可以再抓回來**，不能等動畫播完才能操作。
- **可拖曳的區域設 `touch-action`**，只把拖曳方向交給手勢，避免和頁面捲動互搶；Drawer 內的按鈕、輸入框按下時不觸發拖曳。
- **每個拖曳或滑動都要有點擊替代**（WCAG 2.5.7）：Drawer 有關閉鈕與「取消」、拖曳排序有「上移」「下移」、滑動出現的列操作有選單入口。手勢是加速，不是唯一入口。
- **按住確認**（如按住刪除工單）：按住時進度等速前進，如實呈現剩餘時間；沒按滿就放開，快速彈回。
- **減少動態**：跟手拖曳保留（動作是使用者自己做的）；甩動慣性、回彈拿掉，放開後只用短的淡出收尾，不做位移（與 `globals.css` 一致）。

## 視窗高度、safe area 與捲動

- App 外框、底部固定 UI 用 `h-dvh`；首屏用 `min-h-svh`。不用 `h-screen`、`100vh`：手機網址列會讓高度溢出。
- 設定 `viewport-fit=cover`，固定的頂列、底列、貼邊元素補 `env(safe-area-inset-*)`；手機橫放時左右也要補。
- **軟鍵盤不能蓋住輸入框與底部固定鈕**：聚焦的欄位要捲到可見處；底部固定列在鍵盤出現時跟著上移（`viewport` meta 加 `interactive-widget=resizes-content`，或用 `visualViewport`）。這要在真機驗，模擬器看不到。
- **捲動區加 `overscroll-behavior: contain`**：Drawer、彈窗、對話區內捲到底後，不把捲動傳給背景頁面。
- **有黏頂列或黏底列時**，捲動容器加 `scroll-padding-top`、`scroll-padding-bottom`，錨點目標加 `scroll-margin-top`，聚焦或跳轉到的元素才不會被固定列遮住（WCAG 2.4.11）。

## 載入、回饋與錯誤狀態

**點了就要立刻有反應。**

- **使用者的選擇立即生效**：分頁籤、篩選不等 server；資料回來後以 server 為準，失敗時回彈。
- **內容區用骨架，不用整頁 spinner。** 骨架版型與真實內容一致（表格保留真實表頭、手機用卡片骨架），避免資料到達時跳版。
- **只在真的有等待時顯示**：載入超過 200ms 才換成骨架，這段時間保留舊內容（不用 CSS `delay-*`，舊內容已卸載會變空白）；骨架一出現至少停留 400ms，避免一閃即逝。
- **周邊保持可用**：工具列、搜尋框不卸載；會再觸發請求的控制項（分頁鈕）載入中停用，避免連點。
- **按鈕送出**：按下立即擋住重複送出（停用或忽略再次點擊）；超過 300ms 才在按鈕內左側顯示 `Spinner`、文字改進行式（「送出中」），一出現至少停留 400ms。300ms 內完成的操作閃一下 spinner 會像故障。不蓋全頁遮罩。
- **首次載入的小區塊**失敗時要給錯誤與重試，不讓骨架一直轉。網址沒有實際變動就不導覽、不進入載入中。
- **樂觀更新**（如工單回覆送出）：立即清空輸入框並顯示半透明的「傳送中」；失敗時淡出，把文字與附件放回輸入框並跳錯誤 toast。

**Toast 與操作回饋**

- **Toast 不是唯一入口**：重要結果在頁面上也要看得到（列表更新、狀態變化），toast 消失後不能讓使用者找不到。
- **錯誤 toast 不自動消失，或停留比成功更久**；帶「復原」的 toast 停留要夠長，滑鼠移上或聚焦時暫停計時（WCAG 2.2.1）。秒數以組件預設為準，不自己寫死。
- **複製鈕**（如複製工單編號）：點了圖示換成勾選、文字改「已複製」，約 2 秒後還原。

**錯誤與異常**

- **錯誤頁分情況**，各自說明原因並給出口，不只顯示代碼：

| 情況 | 做法 |
| --- | --- |
| 401 登入過期 | 保留使用者填到一半的內容，重新登入後回到原頁 |
| 403 無權限 | 說明要找誰開通，附回列表的出口 |
| 404 | 附回列表或搜尋的出口 |
| 500 | 「我們這邊出問題」，提供重試 |
| 離線 | 顯示離線提示列，恢復連線後自動重試；離線時送出的內容不丟 |

- **多人同時處理同一份資料**（客服常見，如兩位客服開著同一張工單）：資料被他人更新時顯示提示列，不直接覆蓋使用者正在看或改的內容；即時新進的列表項目不插到使用者眼前的位置，改顯示「3 筆新工單」按鈕，點了才載入。
- **未讀數**超過 99 顯示 `99+`。瀏覽器通知權限只在使用者主動操作後才請求，不在載入頁面時跳出。

**效能底線**

- Core Web Vitals 以 p75 為準：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1。
- 圖片與影片給 `width`、`height` 或 `aspect-ratio`，避免載入後跳版（CLS）；首屏以下的圖加 `loading="lazy"`，首屏主圖不加。

## 導覽、連結與快捷鍵

- 列表的篩選、搜尋、頁碼放**網址參數**，重新整理與分享連結都能還原。
- 列表到詳情的返回鈕：站內上一頁就是該列表時走 `history.back()`（保留捲動位置、篩選、頁碼）；否則開這個分頁上次看的列表網址並捲回。不用單純的 `<a href>` 當返回鈕。
- **導覽用真的 `<a>`**（框架的 `Link`，或 `Button render={<a />}`），不用 `onClick` 加 `router.push`：這樣 ⌘／Ctrl 點擊、中鍵、右鍵「在新分頁開啟」才能用。可點的工單列、卡片也要有真連結（標題是 `<a>`，用 CSS 把點擊區撐滿整列）。
- **外部連結**加 `target="_blank"` 與 `rel="noopener noreferrer"`，並附外部連結圖示（`aria-hidden`）與「（另開新分頁）」的 `sr-only` 文字；站內連結不另開分頁。
- **快捷鍵**：不覆蓋瀏覽器與系統快捷鍵（⌘R、⌘W、⌘F）；依平台顯示 ⌘ 或 Ctrl（用 `Kbd`）；輸入框、可編輯區聚焦時不觸發單鍵快捷鍵；每個快捷鍵動作都要有一般的點擊入口。

## 文案

- **按鈕寫「動詞＋受詞」**（「建立工單」「儲存變更」），不寫「確定」「是」「OK」。破壞性確認鈕寫出動作（「刪除工單」），確認框標題寫出對象與後果（「刪除工單 #1024？刪除後無法復原」）。例外：多選 Drawer 底部的「確認（N）」是確認選擇，可保留。
- **同一個概念全站一個詞**：「工單」不和「案件」混用，「客服人員」不和「客服專員」混用；不確定就查專案既有用詞。
- **中英文、數字之間加半形空格**（「共 12 筆 Email」），中文句子用全形標點，英文與數字縮寫內用半形。
- **日期時間**預設 `Asia/Taipei`、24 小時制；相對時間旁用 `title` 附完整的絕對時間；同一年不顯示年份，跨年才顯示。

## 動態

- **高頻操作不做進出場動畫**：每天重複數十次以上的操作，例如命令面板、鍵盤快捷鍵觸發的動作、工單列表列、分頁籤切換的內容，直接切換。動畫只留給低頻、需要交代空間關係的時刻（開彈窗、Drawer、換頁層級）。
- **換頁轉場只做進場**：桌面淡入；手機往下一層由右滑入、返回由左滑入、同層只淡入。這是刻意保留的例外：方向告訴使用者是進入下一層還是返回。
- 使用者偏好減少動態時只淡入；手勢的處理見上方「手勢」。

## 可及性

- 互動元素用 `button`、`a`，不用可點的 `div`。純圖示鈕有 `aria-label`；裝飾圖示 `aria-hidden`。
- 每個欄位有 label；錯誤用 `aria-invalid` 加 `aria-describedby` 關聯；必填不只靠顏色。
- `Dialog`、`Drawer` 有標題（可 `sr-only`）、Esc 關閉、焦點陷阱，關閉後焦點回到觸發元素。
- **焦點管理**：換頁後焦點移到 `h1` 或 `main`；刪除列表項目後焦點移到下一項（沒有就移到列表標題）；Esc 一次只關最上層浮層；不移除 `focus-visible` 外框，鍵盤操作時才顯示、滑鼠點擊不顯示。
- 狀態不只靠顏色（同時有文字或圖示）；淺色、深色模式文字對比都 ≥ 4.5:1。
- **文字放大**：瀏覽器縮放 200% 或系統大字級時，文字不能被固定高度裁切；包住多行文字的容器不用固定高度。
- 骨架容器 `role="status"`、`aria-busy="true"` 並附 `sr-only` 載入文字，骨架本體 `aria-hidden`；toast、未讀數等動態更新用適當等級的 `aria-live`。
- 表格表頭用 `th scope`，可排序欄位加 `aria-sort`；`<html lang>` 依語系。
